## 2. 扶摇金融数据接入

### 2.1 接口与映射

| 接口 | 用途 | 失败时 |
|---|---|---|
| `GET /api/fund/market/snapshot` | 最新价、涨跌幅、有效时点 | **报错，不降级** |
| `GET /api/fund/market/historical`（interval=1d，前复权，窗口约 3.1 年 ≤ 5 年上限） | 图表、1 年收益、1 年 / 20 日波动、1 年 / 3 年最大回撤、20 日均成交额 | **报错，不降级** |
| `GET /api/fund/profile/detail` | 基金名称、规模（`fund_scale`） | 降级：字段未知，记录 `degraded` |
| `GET /api/fund/performance/indicators-historical` | 跟踪指数 PE-TTM 五年分位 | 降级同上 |
| `GET /api/fund/news/article-list` | 资讯（标题、摘要、原文 URL、发布时间） | 降级同上 |

- 鉴权：服务端 `X-api-key`；密钥只来自 `.env.local`；客户端只访问本站 `/api/*`。
- 解析：Zod 校验 `ApiResponse` 信封与字段；必须 `code === 0`；`null` 字段保持未知。
- 错误码：`2001/2003→UNAUTHORIZED`、`3001/3004→UNSUPPORTED_SYMBOL`、`3002→EMPTY`、`4001` 或 HTTP 429→`RATE_LIMITED`、`5002` 或本地超时→`TIMEOUT`、`5001/5003→UPSTREAM_ERROR`、`100x→BAD_REQUEST`、非 JSON / 信封或字段不符→`MALFORMED`、未配置 Key→`NOT_CONFIGURED`（不发请求）。
- 时点与口径：每个事实带 `asOf`（ISO）与「截至 … / 日线截至 …」标签；超过 10 天标记 `stale`；历史价格标注「前复权」；成交额与规模的单位文档未标注，按元换算为亿元并在口径中说明。
- 周期：图表 1月 / 3月 / 6月 / 1年 / 3年 均由真实日 K 截取；**没有分钟级周期**，未伪装。
- 缓存：服务端内存 5 分钟，避免同一页面重复请求；A/B 研究另有事实快照固定。
- 真实失败从不回退演示数据：`MARKET_DATA_PROVIDER=fuyao` 且无 Key 时页面显示「真实数据源未配置」。

### 2.2 实测发现（真实服务器）

- 缺少 `X-api-key`：返回 HTTP 200 + `{"code":2003,"message":"Missing X-api-key"}`。
- 无效 Key：返回 `code=2003 "Invalid or revoked API key"`。
- 文档写的是「缺失或无效 → 2001」，与线上不一致，代码两者都按鉴权失败处理，并有单测覆盖。

### 2.3 有意不接的能力

- 基金诊断详情：返回结构为「保留上游结构」的 `probabilities / ranges` 等对象，文档未定义含义。接入会诱导模型输出概率性判断，与「不输出确定性预测 / 概率」的边界冲突，因此本迭代不接。
- 费率 `rate_info`：结构未在文档中定义，不解析，避免误读费率；费率保持「未知」。

## 3. LLM 与研究 Agent

- `lib/llm/provider.ts`：OpenAI Chat Completions 兼容；模型、地址、密钥全部来自环境变量；`response_format=json_object`，服务商不支持时自动降级一次；401/403、429、超时、取消、空内容、非 JSON 全部映射为显式错误。
- `lib/agent/research-agent.ts`：固定六阶段，不做开放式循环。模型调用每次研究最多 4 次（规划与回答各最多 1 次修复重试）；每类数据工具最多 1 次；用户取消会中止服务端进行中的请求（E2E 中用 Mock LLM 的调用计数验证：取消后没有发生「生成结论」调用）。
- 降级：规划失败 → 明确标注的默认计划；回答失败 → `status: degraded`，**不显示任何替代结论**，只保留已核验数据与规则视图；鉴权失败 / 未配置 / 数据源失败 → 显式报错。
- 画像最小化：发送给模型 7 个字段（目标、期限、经验、主观偏好、客观承受能力、近期资金需要、应急储备）与推导信号；收入稳定性不发送；UI 中逐项展示「发送给模型的画像字段」与「未发送」字段。
- 不可信输入：资讯标题 / 摘要清洗控制字符与尖括号、截断长度，放入 `external_news` 数据块，系统提示要求忽略其中指令；即使模型复述资讯中的「建议买入」，合规护栏也会删除。
- 不暴露推理：只展示阶段、工具调用状态与最终结构化结论，不展示模型推理文本。

## 4. 个性化与 A/B

`Market Facts → Research Evidence → Personalization Rules → LLM Explanation`

- 规则引擎（第一迭代）决定模块顺序、个人相关度和「为什么与你有关」；LLM 只能从规则给出的风险列表中选择并解释，不能新增风险类别、不能改变等级与顺序。
- 客观严重程度只由事实决定，例如「阶段性深度回撤」由近 3 年最大回撤确定，所有画像相同；用户更激进不会降低它。
- A/B 对比按钮：同一问题先用画像 A 研究，再用画像 B 研究并复用 A 的事实快照。测试断言：两次的 `facts` 完全相等、指纹相同、客观严重程度相同；首要研究模块、发给模型的画像字段与研究优先级不同。

开发中由测试发现并修复的真实缺陷：

1. **取消按钮会重新开始研究**（E2E 发现）：React 复用了同一个 `<button>` 元素，点击「取消」后同步更新状态，元素在浏览器执行默认动作前变成 submit 按钮，表单被再次提交。修复：两个按钮使用不同 `key` 并 `preventDefault`；同时显式取消流读取，并用运行令牌忽略迟到事件。新增服务端侧断言：取消后 Mock LLM 不再收到「生成结论」调用。
2. **zod 泛型推断为输入类型**（类型检查发现）：`fuyaoGet` 改为按 schema 输出类型推断。
3. 测试断言过宽：系统提示词中的「不推断收入」被误判为泄漏，改为只检查发送给模型的数据部分。

## 7. 已知问题与风险

1. **研究延迟较高**：真实推理模型单次研究约 65–80 秒；资讯分支在真实环境中尚无数据（0 篇）。
2. 数值核验是启发式的：只核对带小数 / 百分号或 ≥ 100 的数字，容忍四舍五入；不能识别语义错误（例如把 1 年回撤说成 3 年）。
3. 合规护栏基于规则匹配，可能漏掉新的措辞或误删正常句子（如「不建议买入」也会被删除）。
4. 事实快照与 Provider 缓存保存在单进程内存中；多实例部署时 A/B 复用快照需要改为共享存储。
5. 演示模式下「3年」图表实际为 731 个点（MA20 预热占用 19 个合成交易日），不影响事实层。
6. 资讯只展示标题、摘要与链接，没有读取正文；资讯观点均标注为「未验证」。
